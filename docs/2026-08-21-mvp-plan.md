# QuotaBar MVP Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Build an original macOS menu-bar quota monitor with a glanceable sample-data UI and a provider boundary that keeps authentication out of the first vertical slice.

**Architecture:** `QuotaBarCore` owns provider-neutral models and the `QuotaProvider` protocol. The `QuotaBar` executable owns SwiftUI/MenuBarExtra presentation and refresh state. The MVP ships only `SampleQuotaProvider`; real providers must later implement Keychain storage, HTTPS host allowlists, and redirect rejection behind the same protocol.

**Tech Stack:** Swift 6.2, SwiftUI, Swift Package Manager, XCTest, macOS 26.

---

### Task 1: Define quota domain behavior with a self-check

**Objective:** Specify clamped percentages, reset presentation data, and provider-neutral account/window models.

**Verification:** `swift run QuotaBarChecks`

**Objective:** Make sample data explicit and injectable without coupling the UI to any provider or credential implementation.

**Files:**

### Task 3: Build the original menu-bar monitor surface

**Objective:** Render a dense, glanceable Monitor surface with account rows, window progress, last refresh time, manual refresh, and an unmistakable SAMPLE DATA label.

**Files:**

## Explicit non-goals for MVP

- No Claude/Codex/GitHub/OpenCode/SuperGrok authentication.
- No external CLI execution.
- No auto-update framework.
- No telemetry or analytics.
- No network requests.
- No credentials in persisted app state.
